# 看板与 WIP（并行任务与中断恢复）

并行工作不是直线，所以每种状态各有一个容器：待办池、挂起的工作现场、读完就弃的草稿、已进代码的变更。**这份管到「容器怎么用、什么时候删」，不管单份文档怎么写**（那是 `writing-*.md` 的事）。

## 问题

真实工作不是直线：bug A 改一半发现效果不佳 → 挂起 → 改 B → B 完成并归纳 → 回来继续 A。至少要同时容纳三种东西：多个工作现场、待办池、刚做完还没归纳的成果。没有为它们指定容器，就会全掉进 MEMORY——而 MEMORY 不进 review，于是「做到哪了」这种最需要准确的信息，存在最不可靠的地方。

## 一个状态一个容器

| 状态 | 载体 | 收尾成本 | 判据 |
|---|---|---|---|
| 还没开始，一句话说得清 | `.agents/work/BOARD.md`「待办」表 | 勾掉 = 换表 | 能一句话说清 |
| 做到一半，跨会话还要读 | `.agents/work/wip/<ID>-<slug>.md` | 删前必须蒸馏 | 三天后回来还要读它 |
| 读完就弃的方案 / 草稿 / 报告 | `.agents/work/scratch/` | 直接 `rm -rf` | 不读也不亏 |
| 已进代码、用户能感知 | `CHANGELOG` 的 `## [Unreleased]` | 发版时归位 | 与「做到一半」是两回事 |
| 代码现场（改了哪几个文件） | **git branch**，不用 stash | 合并或删除 | `git branch -v` 一眼看到全部现场 |

目录树见 [layout.md](layout.md) 的「完整结构」。

**分档的理由不是整齐，是删除成本不同。** `wip/` 删前要走三问，`scratch/` 直接删。混在一起会导致「把该蒸馏的当垃圾删了」或「把垃圾当宝贝留着」。

`scratch/` 也是 **agent 产出的合法归宿**：子 agent 每完成一件事都想写份方案/报告，那些内容不能进仓库（是过程），又不能不落盘（长分析会被截断）。写进 `scratch/`，读完即弃。

**不用 stash 当并行现场**：stash 没名字、没说明，一周后没人知道哪个属于哪个任务；branch 名即状态，`git branch -v` 就是现场清单。

> `.agents/work/` 已被 `.agents/*` 的 gitignore 规则覆盖，**不需要额外加 `.gitignore`**。仓库根再开一个 `tmp/` 只会得到两个临时区。

发现第二个临时区（`.agents/scratch/`、根 `tmp/`、`docs/drafts/`）时按三步收：内容并进 `work/scratch/` → **删掉旧目录本身** → **删掉它在 `.gitignore` 里的那一行**。只删目录不改 gitignore，下次有人照着旧规则又建一个；只改 gitignore 不删目录，等于允许它复活。

## 什么时候才建 WIP

**只在「预计会被打断」时建。** 具体：

- 同一会话能做完的 → **不建**，直接用看板；
- 预计中断 ≥ 1 次（等 token、等用户决定、要转去做别的）→ 建；
- 分支不是必需的：多人协作或长命特性才建（`git switch -c fix/xxx`，分支名即状态）；单人 + 本地看板，看板 + `git status` 已够对账。

## 一个 WIP 的五要素

模板：[assets/WIP.template.md](../assets/WIP.template.md)——照抄，别自己发明键名。头部四行是 `状态` / `分支` / `优先级` / `最后动`，正文五个键：`目标`（怎么算好）、`现状`（改到哪）、`决策`（为什么这么走、试过什么不行）、`下一步`（回来第一件事）、`阻塞`（可选）。

**两个承重点**：

- **下一步**——没它，其余四项只是日记；有它，这份记录才是「可以继续执行的任务」。
- **试过什么、为什么不行**——防最贵的一类返工：下次回来把死路再走一遍。

## 分级与看板 schema

两维，不要加第三维（模块、规模、来源）——加维度会让更新表格变成负担，然后表格就没人更新。模板：[assets/BOARD.template.md](../assets/BOARD.template.md)。

| 维度 | 取值 | 判据 |
|---|---|---|
| 优先级 | P0 / P1 / P2 | P0 = 阻塞别人或有数据/安全风险；P1 = 本次迭代必须完成；P2 = 发现了，可以等 |
| 状态 | 待开始 / 进行中 / **挂起** / 待评审 | 只这四值，不要「基本完成」这类模糊态。**「完成」不在其中——完成＝换表** |

**待办 / 挂起表**：表头与列序以 [assets/BOARD.template.md](../assets/BOARD.template.md) 为准（模板是列名的唯一真源），语义如下。

- **ID**：按域起前缀 + 数字（如 `U` 需求 / `M` 能力 / `V` 验收 / `D` 文档），**只增不复用**。
- **下一步**：一句话，具体到「打开哪个文件、改哪一段」；没想清就写卡在哪。**禁用词**：同上 / 待定 / 看情况 / 继续优化。
- **依据**：可查坐标（`docs/x.md §3.2` / `AGENTS.md 硬约束 N` / 短 sha / 用户原话(日期)）。**禁「见上文」**。
- **最后动**：改状态或改下一步时同步改。
- 单元格里的裸 `|` 会切格——写 `\|`，门禁（G12）认这个转义。

**已完成表**：列见同一份模板。

- **ID 填该事项在待办表里的原编号**——完成＝换表，不换号；**从没上过板的**（顺手修的 commit、验收轮）写 `—`，它的身份证是 commit sha。
- **一件事** ≤ 40 字，只写可感知结果；通过率、字节数、覆盖率之类归 commit message 与 CHANGELOG。
- **commit**：短 sha，多个用 `·` 分隔；无代码变更写 `—`。一 commit 一行，时间倒序（最新在上）。
- 同一个 ID 不许两张表都在。

## 板 ↔ wip 的绑定

- 文件名即外键：`wip/<ID>-<slug>.md`。板说「进行中/挂起」就必须有这份文件；`wip/` 里每份都必须在板上有同 ID 的行（孤儿 wip = 垃圾）。
- wip 头部 `> 状态：` 与板上状态**逐字相同**；写 `> 状态：完成` 违规——完成要蒸馏后删档。
- 「待开始」也可以有 wip（已定过口径、还没动手）：判据仍是「跨会话回来要继续读它吗」，不是「必须已经动手」。

## 体量与完成记录两层

「只登记 P0 / P1」在真实项目里不成立——P2 恰恰是最常看的部分（还剩什么没做）。改用机械上限，数值见 [layout.md](layout.md) 的「档位与行数线」。超了不是删行，是**整批降级**：同主题的 P2 合成一行，或搬进 `wip/backlog.md` 只留一句指针。

「已完成只增不删」和「全文有上限」在长项目里必然打架。解法不是删行，也不是压散文，是把完成记录分两层：

- `BOARD.md` 只留**最近若干行**（窗口上限见档位表）；
- 更早的按时间倒序追加进 `BOARD-archive.md`：**同一张表的延续**，表头与列语义完全相同，不是第二份真源；
- 归档区同样受门禁（表头 / 倒序 / 短 sha / 跨文件衔接，见 [gates.md](gates.md) 的「工作现场门禁」），ID 与活跃区共用一个唯一表；
- 活跃区超过窗口 → 告警「该归档了」，不靠人记。

不要做的是「压行数」：把几条约定合并成一句长散文，等于把索引写成论文，下次没人敢改。

## 完成：三问开关

小改动有 3 问必然空答，空答几次后整套会被跳过。所以只问：

1. **用户/升级者会感知到什么？** → 进 `CHANGELOG`
2. **有新的不变量吗？**（「X 恒等于 Y」）→ 契约 `## 条款`，带锚点
3. **有新的坑吗？** → `AGENTS.md ## 硬约束`

**三问全不命中 → 只删 WIP，不蒸馏。** 命中才写。另外三件事永远做：

- 「为什么这么做」进 commit message（这是 1，不是第 4 问）；
- 看板行从「待办」移进「已完成」表，**ID 不换**；短 sha 填 `commit` 列；
- **删掉 WIP 原件**。不归档——归档已完成 WIP 等于把垃圾收进抽屉。

## 放弃也是合法终点

一直挂着的任务比没有更糟：它持续占注意力，每次看看板都要重新判断。

只清理 `进行中 / 挂起`——它们才是持续占注意力的那类；`待开始` 的 P2 挂着是有价值的（还剩什么没做），不按天数清。

**超过 30 天没动，且说不出「下次什么时候会做」** → 放弃：写一句为什么（不是「以后再说」）→ 按上面三问蒸馏掉学到的 → 删 WIP 和分支。

「为什么」落在哪，按这三行判：

| 放弃的东西 | 写进 |
|---|---|
| 产品级「不做」的裁决 | 契约的决策登记（`decisions.md` / MADR `status: rejected` + Considered Options） |
| 某条事实变了，事项因此失效 | 对应契约正文（一句话说清「现在恒是什么」） |
| 只是不做了、没有裁决价值 | 不写，直接删行 |

**不新建「放弃归档」表**：放弃不是完成，也不该有第二个索引。

## 反模式

| 反模式 | 后果 | 该去哪 |
|---|---|---|
| 用 stash 当并行现场 | 没名字没说明，一周后没人知道属于哪个任务 | `git branch` |
| WIP 的「下一步」写「继续优化」 | 等于没写，下次回来仍要重新判断 | 具体到文件与段落 |
| 完成的任务进 `archive/` | 把垃圾收进抽屉，还多一个索引 | 蒸馏后删原件 |
| 一份 WIP 塞三个任务 | 一起挂起、一起遗忘 | 一任务一 WIP |
| 只更新状态不更新「下一步」 | 状态告诉你在哪，下一步才告诉你该干嘛 | 两列同批改 |
| 事项完成后换编号 | wip 文件名、commit、对话引用全断链 | 换表不换号 |
| 看板行里写五段叙述 | 索引退化成散文 | 叙述进 `wip/<ID>-*.md` |
| 为压行数把约定合并成一句长散文 | 不可校验、不可 diff，看板开始腐化 | 完成记录移进归档区 |
| 给放弃的事项建归档表 | 出现第三个索引 | 契约的决策登记 |
