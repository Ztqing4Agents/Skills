# 并行任务与中断恢复

## 问题

真实工作不是直线：bug A 改一半发现效果不佳 → 挂起 → 改 B → B 完成并归纳 → 回来继续 A。三种状态并存：多个工作现场、待办池、刚做完还没归纳的成果。没有为它们指定容器，就会全掉进 MEMORY——而 MEMORY 不进 review，于是「做到哪了」这种最需要准确的信息，存在最不可靠的地方。

## 核心区分：待办 vs 挂起的工作现场

| | 待办 | WIP |
|---|---|---|
| 描述什么 | 还没开始做什么 | 做到哪、为什么这么走、下一步 |
| 一句话说得清吗 | 能 | 通常不能 |
| 存哪 | 任务板 | `.agents/work/wip/`（跨会话） |
| 完成后 | 勾掉 | 蒸馏后删 |

**判据只有一条：跨会话回来要继续读它吗？** 要 → WIP；不要 → `scratch/`。

## 什么时候才建 WIP（避免仪式化）

**只在「预计会被打断」时建。** 具体：

- 同一会话能做完的 → **不建**，直接用任务板；
- 预计中断 ≥1 次（等 token、等用户决定、要转去做别的）→ 建；
- 建的时候同时建分支（`git switch -c fix/xxx`），分支名即状态。

BOARD 也只登记 P0 / P1——P2 待办太多时看板本身就成了负担。

## 一个 WIP 的五要素

```markdown
# WIP: <一句话任务名>

> 状态：进行中 | 挂起 | 待评审
> 分支：<branch>（或「工作树」）
> 优先级：P0 | P1 | P2
> 最后动：YYYY-MM-DD

## 目标
完成后怎么算好（可验收，不是「优化一下」）

## 现状
做了什么、改到哪、动了哪些文件

## 决策
为什么这么走；**试过什么、为什么不行**

## 下一步
回来后第一件事，具体到「打开哪个文件、改哪一段」

## 阻塞（可选）
卡在什么上
```

**两个承重点**：

- **下一步**——没它，其余四项只是日记；有它，这份记录才是「可以继续执行的任务」。
- **试过什么、为什么不行**——防最贵的一类返工：下次回来把死路再走一遍。

## `work/` 两档

```
.agents/work/
├── BOARD.md          ← 看板（唯一，放顶层）
├── wip/              ← 挂起/进行中，删前必须蒸馏
└── scratch/          ← 草稿/方案/分析，随时可 rm -rf
```

分档的理由不是整齐，是**删除成本不同**：`wip/` 删前要走三问，`scratch/` 直接删。混在一起会导致「把该蒸馏的当垃圾删了」或「把垃圾当宝贝留着」。

`scratch/` 也是 **agent 产出的合法归宿**：子 agent 每完成一件事都想写份方案/报告，那些内容不能进仓库（是过程），又不能不落盘（长分析会被截断）。写进 `scratch/`，读完即弃。

> `.agents/work/` 已被 `.agents/*` 的 gitignore 规则覆盖，**不需要额外加 `.gitignore`**。仓库根再开一个 `tmp/` 只会得到两个临时区。

## 三条隔离线

| 状态 | 载体 | 为什么 |
|---|---|---|
| 代码做到一半 | **git branch**（不用 stash） | `git branch -v` 一眼看到全部现场；stash 没名字，一周后没人知道属于哪个任务 |
| 脑子里的上下文 | `.agents/work/wip/` | 过程不进 review，但要跨会话存活 |
| 已进代码、用户能感知 | `CHANGELOG` 的 `## [Unreleased]` | 与「做到一半」是两回事 |

多人协作时把 wip 换成 `docs/wip/`（进仓库共享），但加时限：**超过 30 天没动就要处理**。

## 分级：两维，五值

| 维度 | 取值 | 判据 |
|---|---|---|
| 优先级 | P0 / P1 / P2 | P0 = 阻塞别人或有数据/安全风险；P1 = 本次迭代必须完成；P2 = 发现了，可以等 |
| 状态 | 待开始 / 进行中 / **挂起** / 待评审 / 完成 | 只这五值，不要「基本完成」这类模糊态 |

**不要加第三维**（模块、规模、来源）。加维度会让更新表格变成负担，然后表格就没人更新。

看板 `.agents/work/BOARD.md`：

```markdown
| 任务 | P | 状态 | 分支 | 下一步 | 最后动 |
|---|---|---|---|---|---|
| 预览图标空槽 | P1 | 进行中 | fix/icon-slot | 补 P28 断言 | 11-07 |
| 宿主 401 目测 | P2 | 待开始 | — | 需要真机 token | — |
```

## 完成：三问开关

小改动有 3 问必然空答，空答几次后整套会被跳过。所以：

1. **用户/升级者会感知到什么？** → 进 `CHANGELOG`
2. **有新的不变量吗？**（「X 恒等于 Y」）→ 契约 `## 条款`，带锚点
3. **有新的坑吗？** → `AGENTS.md ## 硬约束`

**三问全不命中 → 只删 WIP，不蒸馏。** 命中才写。另外两件事永远做：

- 「为什么这么做」进 commit message（这是 1，不是第 4 问）；
- **删掉 WIP 原件**。不归档——归档已完成 WIP 等于把垃圾收进抽屉。

## 放弃也是合法终点

一直挂着的任务比没有更糟：它持续占注意力，每次看看板都要重新判断。

**超过 30 天没动，且说不出「下次什么时候会做」** → 放弃：写一句为什么（不是「以后再说」）→ 按上面三问蒸馏掉学到的 → 删 WIP 和分支。

## 反模式

1. **用 stash 当并行现场**——没名字、没说明，一周后没人知道哪个属于哪个任务。
2. **WIP 里写「继续优化」**——「下一步」必须可执行，否则等于没写。
3. **完成的任务进 `archive/`**——WIP 不是文档，归档它是把垃圾收进抽屉。
4. **一份 WIP 塞三个任务**——它们会被一起挂起、一起遗忘。
5. **看板只更新状态不更新「下一步」**——状态告诉你在哪，下一步才告诉你该干嘛。
