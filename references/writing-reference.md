# 写参考

参考类记「外部世界长什么样」——API、DOM 结构、第三方行为、协议字段。它和契约的唯一区别：**契约的真源在我们仓库里，参考的真源在别人手里**，所以我们只能记「什么时候采的、采自哪个版本」。

## 什么时候需要一份参考

- 我们要照着外部结构写代码，而这份结构不能从本仓库推出来；
- 外部会独立升级，且升级会让我们写的东西失效；
- 同一事实要在多处复用（否则写进契约的对应条款就够了）。

**只要不满足第二条，就别建**：不追版本的「外部说明」会立刻变成没人维护的摆设。

## 头注：七键

五键 + 两键（`采集日期:` / `来源版本:`）。模板：[assets/reference.template.md](../assets/reference.template.md)。

```markdown
> 类型：参考
> 读者：<谁，在什么时刻读>
> 真源：<外部系统 / 官网 / 接口文档>
> 更新触发：<外部版本变化、我们升级依赖时>
> 规模上限：600
> 采集日期：2026-11-11
> 来源版本：<外部产品版本号 / 发布日期>
```

`采集日期:` 必须是真的采集日，不是「最后编辑日」——门禁 G5 只用它算新鲜度，改它就是自欺。

## 每条都要带验证方式

一行一条，右侧给一条能重跑的检查（`curl` / `grep` / 一段脚本）。**没有验证方式的条目，过期了没人知道**。

```markdown
| 项 | 值 | 验证方式 |
|---|---|---|
| 侧边栏折叠后的宽度 | 48px | `grep -n '\-\-sb-collapsed' app.css` |
```

## 外部变了怎么办

**整份重采，不在旧表上打补丁。** 打补丁的结果是同一份文档里同时躺着新旧两代结构，读者分不清哪条现行——那正是 [doc-rot-signals.md](doc-rot-signals.md) 的第 1 条。

- 只改一两格却不动 `采集日期`／`来源版本` = 文档会开始撒谎；
- 重采时把旧版结论直接删掉，历史交给 git；
- 重采完顺手跑一次门禁 G5，看日期有没有写错。

## 放哪

1 份放根 `reference.md`，≥ 2 份放 `docs/reference/`（见 [layout.md](layout.md) 的目录表）。**不要**把参考塞进 `docs/contracts/`——类型不同，失效原因也不同。

## 不写什么

- 不写「我们应该怎么用」——那是契约的活；
- 不写外部产品的历史版本对比（除非差异本身是我们要适配的对象）；
- 不写推测：拿不到就写「未采集」，别拿记忆补。
