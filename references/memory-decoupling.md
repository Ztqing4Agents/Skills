# MEMORY 解耦

**这份只管「哪条该搬去哪」，搬完之后文档怎么组织归其它细则。**

## 原理

**MEMORY 膨胀不是它自己长出来的，是「文档体系缺位的症状」。** 当 CHANGELOG 不存在、AGENTS.md 不存在、契约文档里没有对应小节时，这些内容只能堆进 agent 记忆。

所以治本方法不是给记忆分类，而是**给它找到该去的地方**。

## 判据

> **MEMORY 装的是「不进 review 的东西」；文档装的是「进 review 的东西」。**
> 一件事一旦定型、会被别人读到、改错要负责 → 它就该离开 MEMORY。

理由：MEMORY 由 agent 自动维护、不强制审查；文档进 review、有真源、有更新触发。**把需要负责的事放在不进 review 的容器里，等于让错误没有守门人。**

## 解耦路由

| MEMORY 里的内容 | 迁去 |
|---|---|
| 测试手法 / 脚手架陷阱 | 契约 `## 验收` 或测试文件注释 |
| 外部 DOM 锚点 / API 结构 / 版本偏移 | 参考类（带采集日期 + 验证方式） |
| 产品事实 / 不变量 | 契约 `## 条款` |
| 发布基线（tag、行数、用例数） | `CHANGELOG`（或删掉，交给 git tag） |
| 仓库约定 / 禁忌 | `AGENTS.md ## 硬约束` |
| 已完成的决策及其理由 | commit message（`git log -S` 可查） |
| 一次性过程、进度流水 | 删 |
| 跨项目的用户偏好 | 用户级记忆，不留在项目级 |

## MEMORY 只该留三类

1. **当前工作状态**（在进行哪件事、卡在哪、下一步）；
2. **跨项目的用户偏好**（不属于任何单个仓库）；
3. **尚未定型的探索结论**（还不够格写进契约，但下次会用到）。

## 完成标准（可判定）

- 项目级 MEMORY 总行数与单节行数不超过[档位表](layout.md#档位与行数线唯一常量表)里的 MEMORY 一行；
- 没有一节叫「各种」「其他」「杂项」——那是有东西没找到家的信号。

迁完没瘦，说明还有容器缺位（通常缺 `AGENTS.md ## 硬约束` 或 `CHANGELOG`）。

## 执行程序

1. 逐节读，每节问：**这属于哪一类？**
2. 归不进「三类保留」的，查路由表找目的地；目的地不存在就先建容器。
3. **先写进文档、再删记忆**——顺序反了中间态会丢信息。
4. 收尾把「以后新知识该写哪」写进 `AGENTS.md ## 硬约束`，否则下次还会堆回来。

## 反例

```
## 测试脚手架
- 假 DOM 的 querySelectorAll 按选择器字符串开关应答，只能证明……
```

这是**契约**（下一任改测试必须遵守），却住在只有 agent 会读的地方。正确去处是契约 `## 验收` 或测试文件注释——那里会被 review，也更容易在改测试时被发现。
