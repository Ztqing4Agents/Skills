## 门禁清单（G1–G14）

**闸号稳定**：文档、脚本报错、看板里的「依据」都用这个号，不许重排。

| 号 | 检查 | 判据 | 失败时 |
|---|---|---|---|
| G1 | 文件白名单 | 仓库里的 `*.md`（含未跟踪）⊆ 允许清单 | 红 |
| G2 | 头注完备 | 带 `类型:` 的文件必须有 `类型:` `读者:` `真源:` `更新触发:` `规模上限:`；参考类另加 `采集日期:` `来源版本:`；`README.md` / `AGENTS.md` / `CHANGELOG.md` 豁免 | 红 |
| G3 | 头注取值 | `规模上限:` 等于类型对应档位（见 [layout.md](layout.md) 的档位表） | 红 |
| G4 | 必填章节 | 契约→`## 范围`、`## 条款`、`## 验收`；规范→至少一个含「验收」的 `##`；参考→不强制 | 红 |
| G5 | 参考类时效 | `采集日期:` 存在且是 `YYYY-MM-DD`；超期 | 缺→红 / 超期→告警 |
| G6 | CHANGELOG 结构 | 含 `## [Unreleased]`；版本标题为 `## [x.y.z] - YYYY-MM-DD`（可带 ` [YANKED]`）；`###` 类别只有官方六类 | 红 |
| G7 | **指路坐标存活** | 契约正文里的 `§x.y` / `附录 X.n` 能 grep 到标题编号；`AGENTS.md 硬约束 N` 命中 `^N. **` | 红 |
| G8 | **引用可达** | md 相对链接、`AGENTS.md` 文档地图里的路径、正文点名的 `docs/…` / `.agents/…` 都存在；同一目标只报一条 | 红 |
| G9 | 零行号 | 禁止把行号写进正文：`文件名` + 冒号 + 数字，或「第 N 行」；先剥围栏代码块与行内代码再匹配 | 红 |
| G10 | AGENTS 体量 | 超过 `AGENTS.md` 档位 | 告警 |
| G11 | 文档体量 | 超过头注声明的档位 | 告警 |
| G12 | 工作现场一致性 | 看板两表列名 / ID 词表 / 取值 / 依据坐标 / wip 双向绑定（见下） | 红（`.agents/work/` 不存在则跳过） |
| G13 | README 体量与描述 | 超体量线；简短描述与 `descriptionSource`（默认 `package.json`）的 `description` 不一致 | 告警 |
| G14 | 计数与承诺词 | 手写的会变计数（`N 条` + 名词、`共 N 例` / `共 N 行`、`N 个文件`）；`后续版本` / `以后会` / `即将` 未带看板 ID（编号引用不算） | 计数→告警 / 承诺词→红 |

## 三条最容易写错的

**白名单必须排除 `.agents/**` 与所有 gitignored 路径。** 否则 `scratch/` 里的草稿会被判红，等于 scratch 不可用——这是这类门禁最常见自伤。

**`AGENTS.md` 与 `CHANGELOG.md` 豁免头注检查。** 它们有各自的固定形状，硬塞 `类型:` 只会让模板变丑。

**G7、G8 是这个体系唯一的「指路校验」。** 其余各条都只查结构。要认清它的边界：它挡得住「指向已删章节 / 已改名文件」，**挡不住「代码改成 32px 了，文档还写 28px」**——数值失真只能靠 review 与 [doc-rot-signals.md](doc-rot-signals.md)。

## 判红 vs 告警

- **判红**：结构缺失、矛盾、越界——有唯一正确答案。
- **告警**：体量、时效——「该去看一眼」，处置取决于上下文（合并？迁出？重采？）。

一旦「长度超标」判红，达标手段必然退化成删掉最长的边缘条件——而那恰恰最不可再生。

## 工作现场门禁（看板 + wip）

工作现场不入库（`.agents/work/` 被 gitignore），所以**存在即校验、不存在即跳过**——但跳过条件必须窄：

- 只有 `.agents/work/` **整个不存在**才 skip（新克隆）；**目录在、`BOARD.md` 不在 ⇒ 红**（板被删或被挪走，是事故不是干净）。
- 列语义见 [board-and-wip.md](board-and-wip.md) 的「看板 schema」；门禁只管**每一格能不能被证明**：
  - `ID` 在词表内、跨两表不重复；`P` / `状态` 在枚举内；`最后动` 是日期。
  - `下一步` 非空、不含禁用词（词表见 [board-and-wip.md](board-and-wip.md) 的「看板 schema」）。
  - `依据` 逐个坐标核：`docs/…md §x.y` 的标题要 grep 到、`AGENTS.md 硬约束 N` 要命中 `^N. **`、任何 `.agents/…` 路径要存在、7–40 位 sha 要 `git cat-file -e`（非 git 环境降级为告警）。
  - 已完成表的 `commit` 也验存在性——否则 `deadbeef` 是绿的，而依据里的 sha 却查，前后不对称。
  - 板说「进行中 / 挂起」必须有 `wip/<ID>-*.md` 且头部状态逐字一致；`wip/` 里每份都要在板上有同 ID 的行。
- 体量只告警（阈值见 [layout.md](layout.md) 的档位表），不判红。
- 归档区（`BOARD-archive.md`）与活跃区同一套列语义：固定表头、时间倒序、短 sha 存在、ID 跨两文件唯一，且**首行不得新于活跃区末行**——否则说明抽的不是尾部，历史顺序会错。

**每个门禁都要有一条「在真实树上跑一遍」的用例。** 夹具全绿、真仓红，是结构解析型门禁最典型的假安全：夹具是作者按自己的理解写的，共享同一个误解。

**结构解析型门禁的四个必测破坏**（每缺一个就留一个静默洞）：

1. **缺分隔行**——解析器常把第一行数据当分隔行吃掉，那行不经任何规则却 exit 0。
2. **切格与转义**——`split('|')` 不认 `\|`；头注一旦写了「用 `\|` 转义」，文档与实现就互斥、照文档写必红。要么实现认转义，要么别写这条约定。
3. **非文件条目**——不筛类型时，`wip/U1-x.md/` 这种「以 `.md` 结尾的目录」会让读取抛 `EISDIR`，stdout 一行 `RED` 都没有、只有栈。
4. **skip 边界**——只有「整个目录不存在」能 skip；父目录在就该红。

## 门禁的载体与输出契约

规范不落地就只是建议，所以三件事必须固定：

- **位置与命令**：`scripts/check-docs.mjs`，`node scripts/check-docs.mjs --root .`；自测 `--selftest`；机器可读 `--json`。
- **配置**：仓库根 `.docs-standards.json`（可缺省），至少能配 `whitelist`、`idPrefixes`、`limits`、`descriptionSource`。缺配置时，需要配置才能判的闸（G1）记 `skip`，不许误报红。
- **输出契约**：每个问题一行 `路径:行号 G<闸号> <red|warn> <原因>`，末尾 `docs-standards: N red, M warn, K skip`；有红则 `exit 1`。**没有稳定输出格式的门禁，修的人只能猜。**

| 时机 | 跑哪些 |
|---|---|
| pre-commit（要快） | G1 白名单、G9 零行号、G14 计数与承诺词 |
| CI | 全量 G1–G14 |
| 交付 / 发版前（人看） | G7 指路坐标、G8 引用，加 [doc-rot-signals.md](doc-rot-signals.md) 的审计 |

## 实现口径（脚本实际怎么判）

规范给判据，这里给**实现侧的取舍**。两者冲突时以本节为准，并且要回头把上面的判据改对——不是反过来。

- **白名单反向检查只对具体文件生效**：无通配条目（`spec.md`）没命中 → 红「缺失或改名」；通配条目（`docs/**`）暂时没命中不报。
- **扫描范围（全闸集，G1 另按白名单判）**＝受版本控制的 `*.md` 加上未跟踪的 `*.md`（`git ls-files` ＋ `git ls-files -o --exclude-standard`），排除 `.agents/**` 与被 ignore 的路径；`archive/` 下的归档件按「归档于 <日期>」头放行，不按类型头注判。
- **G9 / G14 先剥围栏代码块与行内代码再匹配**：规则文件必须能引用它禁止的模式（写「禁 `x.ts:12`」不该自己被判红）。
- **G14 排除编号引用**：`第 1、4、5 条`、`§2.3` 是交叉引用，先抹掉；只认 `共 N 例` / `共 N 行`、`N 条` + 名词、`N 个文件`。
- **G7 两级兜底**：先在本文件找标题编号，再在仓库内找。
- **G8 三趟 + 去重**：链接 → 文档地图 → 正文点名路径；同一文件同一目标只报一条，优先级 链接 > 地图 > 正文。链接这趟先按所在目录解析、再按仓库根兜底，含 `<`、`{`、`*`、`…` 的示例路径跳过。**地图这趟**按仓库根判：单段目录（`wip/`）跳过（相对说法），带父级的（`docs/reference/`）照判。**正文这趟只判 `.md` 文件**，目录说法一律交给地图，`docs/…`、`docs/**`、`*.md` 这类占位与通配过滤。
- **G12 依据逐坐标核**：`docs/x.md §3.2` 要求文件存在且该文件真有 3.2 标题；裸 `§3.2` 走仓库级兜底；`.agents/…` 与其余 `.md` 路径要存在；7–40 位 sha 走 `git cat-file -e`；`用户原话(YYYY-MM-DD)` 验日期。一个坐标都认不出 → 告警（散文依据不可校验）。`commit` 列同套机制，`—` 跳过。
- **G12 的 `wip/` 只认文件**：`<ID>-<slug>.md` 才算绑定；`wip/backlog.md` 这类不参与。
- **G13 的「简短描述」**取 `# 标题` 后第一个非空普通段落的第一句；开头是徽章 / 列表 / 表格 / 引用 / 代码块 → 视为取不到，跳过。
- **git 不可用时**：G1 降级为目录遍历，报告里记一条 `G0 skip` 说明原因。

## 已知边界

- G1 靠 git 认「受版本控制」，但未跟踪的 md 同样计入扫描；完全不是 git 仓库时退化为目录遍历。
- 只解析 markdown 表格（行首 `|`）；HTML 表格与缩进式定义列表不在范围内。
- 跨文件指路坐标只查编号存在性，**不校验引用语义是否指向正确的文档**。
- sha 校验要求本机有 git 且对象在库内（浅克隆里较早的 sha 可能查不到）；拿不到 git 时降级为告警。
- G8 无法区分「示例路径」与「真实引用」：文档里当例子写的 `docs/x.md` 会被判红——要么放进围栏代码块，要么接受这条噪音。
- `*.template.md` 不豁免：模板是给项目照抄的骨架，不是项目文档。别把模板留在项目仓库里（会被 G2/G5 判红）；要用就改名成真文件。

## 门禁自身的验证

改门禁的人不能让门禁自证。每加一道闸，在独立工作树上做四次破坏性验证：

```bash
git worktree add /tmp/gate-probe -b probe/gate
cd /tmp/gate-probe
# 1) 放一个不在白名单的 md（含未跟踪的）→ 必须红
# 2) 把白名单里的文件改名 → 必须红，且报「缺失或改名」而非「读不到文件」
# 3) 改一个被判据约束的值 → 对应闸必须红
# 4) 改掉使数字不一致的引用 → 对应闸必须红（证明它不是恒真）
git worktree remove /tmp/gate-probe
```

把这四次写成 `--selftest`，否则它一定退化成「跑一次绿就交」。

还有一层：**谁写的门禁，就不能是唯一写夹具的人。** 同一人写的夹具与实现会共享同一个误解——按同一份规格换人重写自测，通常立刻能抓出「缺分隔行吞首行」「`.md` 目录崩栈」这类实现缺陷。自测只证明「按作者的理解是对的」。

## 与人的协作

- **删文档需要人确认**：agent 可以列清单、可以提议，但不自行删一份别人可能在读的文档。
- **白名单变更 = 一次人工审查**：新建文档必须同批改白名单，这个摩擦是特性不是缺陷。
- **失败时不许绕过**（`--no-verify`、注掉检查）——绕过一次就永久失效。
