# 目录与档位

仓库长什么样、每类文档能有多大。**门禁怎么判在 [gates.md](gates.md)。**

## 目录：按需创建

**同一类型超过 1 份才建目录。**

| 规模 | 布局 |
|---|---|
| 契约 1 份 + 参考 ≤ 1 份（最常见） | 全放根目录：`AGENTS.md`、`CHANGELOG.md`、`spec.md`、`reference.md` |
| 契约 ≥ 2 份 或 参考 ≥ 2 份 | 建 `docs/`，按内容类型分子目录 |
| 有必须留档但不维护的东西 | 才建 `docs/archive/` |

根目录放「每次开工都会用到」的东西。为 1 份 spec 建 `docs/`，等于要求每个新人先学「为什么它在那儿」。

### 完整结构

```
AGENTS.md                 ← 根：agent 每次开工读
CHANGELOG.md              ← 根：发版时读
spec.md                   ← 契约（1 份）
reference.md              ← 参考（1 份才放根）
docs/
  contracts/              ← 契约（≥ 2 份时）
  reference/              ← 参考（≥ 2 份时）
  archive/                ← 只读，默认不存在
.agents/
  MEMORY.md               ← 系统自管（唯一进 git 的，需 `!.agents/MEMORY.md` 白名单）
  work/
    BOARD.md              ← 看板
    BOARD-archive.md      ← 完成记录溢出（只追加、时间倒序）
    wip/                  ← <ID>-<slug>.md，删前必须蒸馏
    scratch/              ← 草稿/方案/分析，随时可清空
```

**`契约 / 规范 / 参考` 是头注 `类型:` 的取值；`docs/archive/` 是目录，不是类型。** 目录按内容类型分，两套维度混用会得到 `contracts/ reference/ archive/` 这种一半内容一半生命周期的怪结构。

### 三条硬规则

- **空目录是罪**——它会邀请人往里塞东西。
- **不要按 PARA 建四层**（Projects/Areas/Resources/Archives）：`Projects` 由看板承担，`Archives` 由 git 承担。
- **目录结构不需要文档说明**（会腐化）；需要的是每份文件自己的头注。

## `archive/`（默认不存在）

- 只在「必须留在仓库、但已不维护」时创建（二进制、外部交付物、法务留档）；
- 每个文件顶部：`归档于 <日期>，由 <新位置 / commit> 取代`；
- **禁止**在里面判断「现在是什么」——它只回答「过去是什么」；
- 内容上的历史**优先交给 git**，archive 只装 git 装不下的东西。

## 档位与行数线（唯一常量表）

**本表是这些数字的唯一真源。** 其余文件只判断、不复述数字；`scripts/check-docs.mjs` 的 `LIMITS` 默认值必须与本表逐项相等——门禁要能离线跑，所以它是唯一允许的常量副本，改表同批改脚本。

| 对象 | 上限 | 超线时 |
|---|---|---|
| 契约（`类型：契约`） | 300 行 | G11 告警 |
| 规范（`类型：规范`） | 400 行 | G11 告警 |
| 参考（`类型：参考`） | 600 行 | G11 告警 |
| `AGENTS.md` | 100 行 | G10 告警 |
| `README.md` | 120 行 | G13 告警 |
| 参考类 `采集日期` 时效 | 180 天 | G5 告警 |
| 看板「待办」表 | 12 行 | G12 告警 |
| 看板全文 | 70 行 | G12 告警 |
| 看板「已完成」活跃窗口 | 12 行 | G12 告警 |
| 项目级 `MEMORY.md` | 60 行（单节 15 行） | 无门禁，靠 review（见 [memory-decoupling.md](memory-decoupling.md)） |

**本表只收跨文件复用的体量与时效常量。** 只在单一细则里成立的数值（CHANGELOG 单条主句 60 字、看板「一件事」40 字、README 目录 100 行）就地定义，不搬进来——为了统一而制造一堆指针，比重复更难读。
