# 写 README.md

遵循 [standard-readme](https://github.com/RichardLitt/standard-readme/blob/main/spec.zh-CN.md) 的**形状**（节与顺序、必需项、简短描述、目录、许可证在最后），本文只补它答不了的那半边：**同一件事在四份文档里各归谁**。两条一起满足才叫合规。

> 文中以「一个无可执行入口的 DSH 前端插件」为示例，规则本身与项目无关。

## 定位：README 只有一个读者

**还没装的人**，以及**装完想知道能干嘛的人**。不是给维护者看的，也不是给 agent 看的——那两类各有其家。

| 文件 | 回答什么 |
|---|---|
| `README.md` | 这是什么、值不值得装、装完能干什么 |
| `AGENTS.md` | 这个仓库怎么干活（命令、测试、硬约束、文档地图） |
| 契约（如 `spec.md`） | 现在必须成立的事实 |
| `CHANGELOG.md` | 从旧版本升上来要注意什么 |

**README 一旦开始讲实现，它就会随实现腐化，而每位新访客都得先读一遍。**

## 节与归属（覆盖 standard-readme 的每一节）

| standard-readme 节 | 状态 | 写什么 | 不写入什么（归谁） |
|---|---|---|---|
| 标题 | 必须 | `<包名> _(<读者叫法>)_`，斜体括号里放人话名字 | 版本号 / 分支 → `CHANGELOG.md` / git tag |
| 横幅 | 可选 | 不用：没有 CI 出图 | — |
| 徽章 | 可选 | 不用：没有 CI、不发包，徽章只能骗人 | 构建状态 / 覆盖率 → 真跑起来再说 |
| 简短描述 | 必须 | 一句话，**<120 字符**，逐字等于 `package.json` 的 `description` | 能力清单 → 用法节；数值规格 → 契约 |
| 长描述 | 可选 | 2–3 行：为什么装它、装完在哪看到它 | 逐项功能 → 用法；边界 → 「它不做什么」 |
| 目录 | 必需（**<100 行可省**） | 链接**所有** `##`；不必链 `###`（除超长节） | — |
| 安全 | 可选 | 只在需要强调时写 | 权限与隐私声明 → 「它不做什么」 |
| 背景 | 可选 | 动机、抽象依赖、知识来源 | 当初为什么这么定 → git log / 契约的判据章 |
| 安装 | 默认必须 | 装到哪、粘什么（**代码块**）、装完去哪看 | 测试与门禁命令 → `AGENTS.md`；包结构 → `AGENTS.md` |
| 用法 | 默认必须 | **用户怎么操作**：点哪、选什么、看到什么变化 | 「应该长什么样」的契约 → 契约；具体数值 → 契约；实现原理 → 参考表 |
| 额外部分 | 可选 | 领域相关的分节（例：能隐藏什么 / 它不做什么 / 设置存在哪 / 已知限制），每块一个 `##` | 选择器 / 样式表 / 存储键 / 探针 → 契约；开发盲区 → 契约的已知陷阱 |
| API | 可选 | 有公开 API 才写；没有就留一行指针 | 契约细节 → 契约 |
| 维护者 | 可选 | 只列对项目方向负责的人 | 联系方式 → 仓库 owner；单人仓库写了会腐化 |
| 致谢 | 可选 | 对项目有实质帮助的人或事 | 依赖清单 → `package.json` |
| 如何贡献 | 必需 | 一句「在哪问 + 收不收 PR」+ 三份文档指针 | 完整开发流程（命令 / 硬约束 / 文档地图）→ `AGENTS.md` |
| 许可证 | 必须且**最后** | SPDX 标识符或 `UNLICENSED` + 持有人 | 依赖的许可证 → 有依赖再单开一节 |

判据只有一句：**这条信息换一份文档写，读者会不会找错地方？** 会 → 它属于这里；不会 → 它属于更靠里的那份。


## 三个冲突怎么调

### 1 「用法要有代码块」，但这东西没有可执行入口

standard-readme 要代码块，**意图是「可复现」**，不是「必须有围栏」。没有 CLI、没有 import、没有 HTTP 入口的项目（纯 UI 插件、桌面配置、设计系统），用户是在界面里点。

规则：**有可执行入口（命令 / 导入 / 请求）→ 必须代码块；没有 → 用编号步骤 + 一张「选什么 → 界面怎么变」的表格代替**，且第一步必须写清「在哪找到它」。判据是读者照着能做完、不必猜。

**安装节不享受这条豁免**：它总有一条能粘的东西（命令，或「插件管理 → 安装 bundle → 选目录」这样的导航路径）。

### 2 长度

standard-readme 不管长度；本规范仍给 **≤120 行**，但它是**警报线，不是目标**：越线时按下面六类逐条查泄漏，而不是先删内容。

硬指标只有三条——**简短描述 <120 字符、目录覆盖所有 `##`、许可证在最后一节**。

理由：standard-readme 自己按 100 行给「目录是否必需」分档，说明行数是被它承认的复杂度信号。

### 3 简短描述 <120 字符，而 `package.json` 的 `description` 写了一长串

**改 `package.json`，不改 README**：被 `npm view` 与包管理器读的是那一份，README 只是抄一遍。描述本身也只该有一句「这是什么」——规格数字不属于描述。

**两处必须逐字相同**（含标点）。

## 必须删掉的六类（附归宿）

| 类别 | 典型写法 | 该去哪 |
|---|---|---|
| 测试怎么跑 | `node test/smoke.mjs`、用例数、分组说明 | `AGENTS.md` |
| 门禁与检查 | 「八道闸」、基线比对、冻结项 | `AGENTS.md` + 契约的测试章节 |
| 实现原理 | 选择器、DOM 属性名、CSS 类名、探针机制 | 契约文档 |
| 具体数值 | 预览盒尺寸、行高、竖线坐标 | 契约文档 |
| 内部标识符 | 存储键名、常量名、函数名 | 契约文档 |
| 开发盲区 / 技术限制 | 「探针没覆盖某一层」 | 契约的「已知陷阱」 |

**删的标准是一句话**：一个「只装插件、不读源码」的人需要知道这段吗？不需要 → 删。

## 谁保证它不腐化

README 是唯一一份「作者不常读、访客天天读」的文档，所以它靠机器守，不靠自觉。示例项目的四道：

- **反向闸**：README 不得出现像素值、DOM 属性名、类名前缀、样式表常量名、浏览器存储 API、探针字样；同时必须够长（如 >1500 字符）、有 ≥3 个 `##`、并点名用户要打开的那个设置分区。前者防止它退回技术笔记，后者防止它烂成三行存根。
- **字符串闸**：发布面的关键事实（例如「打包面的已知缺口」）那句话必须还在——那是用户能看见的唯一一条打包信息。
- **链接闸**：所有 markdown 链接与行内代码里的路径都要真实存在；删文件不改 README 会红。
- **承诺闸**：「后续版本 / 以后会 / 即将」必须带任务板 ID。README 里没有主体的承诺，等于给访客留了一个永远不来的版本（实测两条都过期了）。

## 图片

一张截图胜过三段文字，但**图会过期**：标明它对应的版本，放在它说明的那一节旁边。不要建一个只放图的目录。

## 反例（真实踩过）

279 行的 README：一个「能做什么」占 167 行，九个区域每节都夹着选择器与 DOM 属性；「实现要点」与「开发与验证」两节共 37 行是纯技术内容，而 `AGENTS.md` 里已有更完整的版本；「安装」排在第 225 行。

**症状**：读者要滚过两百行才知道「怎么装」，真正的技术读者又嫌它比契约浅。

**修法不是删信息，是把它送回各自的容器**：契约拿到几何与判据，`AGENTS.md` 拿到命令，README 只留「装上之后你会看到什么」。
