# 写契约 / 参考 / archive

## 一、契约类（living）

### 头注（必填，五键）

```markdown
> 类型：契约
> 读者：<谁，在什么时刻读>
> 真源：<代码 / 测试在哪>
> 更新触发：<什么改动必须同步改这里>
> 规模上限：<契约 300 / 规范 400 / 参考 600>
```

**参考类**是同一份头注再加两键：`采集日期:`、`来源版本:`。

门禁校验三件事：`类型:` 存在、`规模上限:` 的值取自固定集合、参考类有 `采集日期:`。**锁的是键与取值集合，不是文件里所有数字**。

### 固定章节词表（顺序自由，存在性必填）

| 类型 | 必填章节 | 可选章节 |
|---|---|---|
| 契约（reference 型） | `## 范围`、`## 条款`、`## 验收` | `## 术语`、`## 决策` |
| 契约（说明型，如规范） | `## 问题`、`## 决策`、`## 代价` | `## 被否掉的方案` |
| 规范（领域编号章节） | **只要有一个含「验收」的 `##` 章节** | 其余章节自由编号（§1 §2 …） |

章节名固定 → agent 能 grep 定位，不必读全文。顺序不固定 → 避免「这一节该放第几」的无意义论证。

**`类型：规范` 是例外**：这类文档的章节是领域编号（`## 1 五条原则` … `## 12 判据与已知陷阱`），硬套三节模板会要求重排一份已经 300 行的真文档。它只强制一件事——**必须有一个含「验收」的章节**，因为那是唯一有行动价值的部分。

### 条目形态：一句断言 + 锚点 + 失效触发器

- ✗ 「结构应保持简洁」——不可证伪，十年后还在，且没人能执行
- ✓ 「`.hid_previewGlyph` 恒占 28px（锚点：`PAGE_CSS` 的 `--hid-slot`）；宿主改槽宽即失效」

**锚点必须是能在代码里 grep 到的东西**（符号名 / 选择器 / 常量）。写「大约 28px 左右」等于没锚点。

### 两条边界

- **`## 条款` 里不写「为什么」**——理由进 `## 决策` 或 commit message。混在一起没人能一眼找到规矩。
- **`## 验收` 每条都必须是命令或可观察现象**。「应当保持一致」等于没写。

### 改稿四问（任一卡住就不写）

1. **这句话让文档里哪句变假了？** 有 → 改那句，不许新增；没有 → 才追加。
2. **它点名的符号 / 数字现在还在吗、还对吗？** 不在 → 删或改，**不许补写「以前是」**。
3. **这层保证还有别处承担吗**（测试 / lint / 类型）？有 → 删，别抄第二遍。
4. **删了它谁会做错事？** 说不出人 → 删；说得出 → 留下并写清失效触发器。

**追加合法的唯一条件**：新条目有自己的锚点或触发器。同一小节**连续 3 次**编辑只增不减，就是腐化信号——该合并或迁出了。

## 二、参考类（reference，外部契约）

- 头注七键（五键 + `采集日期:` + `来源版本:`）——外部会变，这是它唯一的失效原因；
- 每条附**验证方式**（一条命令 / 一个 grep），否则过期了没人知道；
- **不追代码版本**：外部变了整体重采，不在旧表上打补丁；
- 只描述**外部长什么样**，不写「我们应该怎么用」——后者是契约。

## 三、`archive/`（默认不存在）

- 只在「必须留在仓库、但已不维护」时创建（二进制、外部交付物、法务留档）；
- 每个文件顶部：`归档于 <日期>，由 <新位置 / commit> 取代`；
- **禁止**在里面判断「现在是什么」——它只回答「过去是什么」；
- 内容上的历史**优先交给 git**，archive 只装 git 装不下的东西。
